# Срез — отчётность магазинов

Интерфейс «Рабочий стол», React / TypeScript, Django и PostgreSQL. Развёртывание через Docker Compose / Portainer за nginx.

Рабочий адрес: **https://srez.studio313.ru/**. Для Portainer: репозиторий `https://github.com/Studio313-krd/srez.git`, ветка `main`, файл `compose.prod.yaml`. Переменные окружения и секреты задаются в настройках стэка, рабочая база переносится отдельной копией.

Локальный сервис: **http://127.0.0.1:8087/**. Управление: **http://127.0.0.1:8087/management**.

14.09.2026 импортированы 83 магазина (74 Мильстрим, 9 Культура крепкого), 200 записей сотрудников, 7 юрлиц, 2 595 дневных планов и 1 370 срезов с показателями. Значения и формулы всех 89 исходных листов доступны в «Управление → Источники».

Для офиса оставлен общий аккаунт **Администратор**. Вход `demo.office` и `demo.store` отключён. На рабочем сервере созданы 83 отдельных аккаунта магазинов: каждый видит только свою точку. Первичные пароли передаются владельцу отдельным файлом вне Git. Четыре демонстрационных магазина сохранены для истории и исключены из рабочего интерфейса. Кадровые записи сотрудников не являются логинами.

В «Управлении»: магазины и назначения сотрудников, ставки и вакансии, планы с версиями, графики и особые дни, реквизиты юрлиц, исходные листы, сверка расхождений, уведомления, смена пароля и журнал действий. Администратор может заполнять и исправлять показатели всех магазинов из рабочего стола. `/admin/` перенаправляет в новый интерфейс; технический Django admin — `/technical-admin/`.

Рабочий стол показывает таблицу выбранного времени: 13:00, 17:00 или закрытие. Пустые отчёты и магазины без строки видны в счётчике «Нет отчёта» и фильтре «Требуют внимания». «Опаздывает» применяется только при известном истёкшем сроке. Фильтр «Замечания и неполные» и кнопка «Задать вопрос магазину» помогают разобрать неполные данные. Основной шрифт — 16 px, подписи — минимум 14 px. Левая панель сворачивается; её состояние запоминается. Во всех рабочих таблицах доступны поиск и сортировка по столбцам, экспорт найденных строк с выбором CSV или Excel (.xlsx).

## Повторный импорт сохранённого снимка

Оригиналы и подготовленный пакет находятся в `.local/import/` и не включаются в Docker-образ. Повторный импорт не создаёт дубликаты, ручные исправления сохраняются.

```powershell
docker compose --env-file .local/preview.env -p srez-preview cp .local/import web:/tmp/srez-import
docker compose --env-file .local/preview.env -p srez-preview exec -T web python manage.py import_sources /tmp/srez-import --apply
Get-Content -Raw -Encoding utf8 scripts/verify_import.py | docker compose --env-file .local/preview.env -p srez-preview exec -T web python manage.py shell
```

`scripts/inspect_registry.py` читает Excel, `scripts/prepare_import.py` преобразует сохранённые снимки. Google-таблицы прочитаны через подключённый Google Drive / Sheets. Автосинхронизация с Google не планируется по решению пользователя. После перехода новые отчёты и планы ведутся в сервисе; прежние таблицы сохранены для справки. Сервис не записывает изменения обратно в источники. `.local` содержит рабочие данные и реквизиты доступа, её нельзя включать в публикацию исходников.

## Проверки

```powershell
npm run build
docker compose --env-file .local/preview.env -p srez-preview exec -T web python manage.py test reports --noinput
npm run test:e2e
python deploy/backup.py --env-file .local/preview.env --project srez-preview --restore-check
```

Серверные тесты работают в отдельной временной БД. Playwright использует установленный Chrome и проверяет импортированный сервис без изменения рабочих данных. Проверка копии восстанавливает её в отдельную временную БД.

Frontend для разработки: `npm run dev -- --port 4317 --strictPort`, proxy на Django `127.0.0.1:8000`. Backend: `.venv/Scripts/python backend/manage.py runserver 127.0.0.1:8000` при `SREZ_DEBUG=true`, после установки `backend/requirements.lock` и миграций. SQLite для разработки отделена от импортированной Docker-базы; актуальные данные проверяйте на **порту 8087**.

Архив первоначальных макетов: `/design` или `/?v=a&role=office` только в режиме разработки. В производственной сборке эти адреса открывают рабочее приложение.
