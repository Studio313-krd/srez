# Подключение уведомлений Telegram и MAX

Боты отправляют уведомления в офисные чаты. Они не принимают отчёты: кнопка в сообщении открывает нужный день, магазин и срез в сервисе. На 14.09.2026 создан Telegram-бот [@srez_notify_bot](https://t.me/srez_notify_bot), его токен указан в Portainer. Пользователь подключит офисную группу позже; отправка выключена. MAX-бот пока не создан. Реальная доставка ещё не проверена.

При проверке 14 сентября сервер не установил TCP-соединение с `api.telegram.org:443` (тайм-аут), хотя GitHub и MAX доступны. Перед включением Telegram проверить исходящий доступ сервера к API и при необходимости настроить доверенный сетевой маршрут у владельца сервера. Верность токена пока не подтверждена ответом Telegram. Проверку TLS не отключать; токен не передавать сторонним публичным прокси.

## 1. Создать Telegram-бота

В Telegram откройте [официального BotFather](https://t.me/BotFather), отправьте `/newbot`, задайте имя и свободный username. Сохраните выданный токен. Эти шаги описаны в [инструкции Telegram](https://core.telegram.org/bots/tutorial#obtain-your-bot-token).

Название можно задать «Срез уведомления». Описание: «Уведомления для офиса о сдаче отчётов магазинами и ответах на вопросы. Работа с отчётами — в сервисе Срез».

Уже созданного бота заново создавать не нужно. Добавьте `@srez_notify_bot` в офисную группу и разрешите отправлять сообщения. Команда `/start` не обязательна: сервис умеет определять группу по событию добавления бота (`my_chat_member`). Программист один раз связывает нужную группу со стендом по шагу 3. После этого сотрудникам ничего писать боту не нужно. Если событие добавления уже устарело, `/start@srez_notify_bot` можно использовать как запасной способ получить ID группы.

## 2. Создать MAX-бота

Откройте [MAX для партнёров](https://business.max.ru/), создайте и верифицируйте профиль организации. Затем «Чат-боты» → «Создать», заполните карточку и отправьте на модерацию. После неё получите токен в настройках бота. Создание требует верифицированного профиля бизнеса; [официальный порядок MAX](https://dev.max.ru/docs/chatbots/bots-create/create).

Добавьте бота в офисный чат. Для получения события добавления при первичной настройке назначьте его администратором чата: это требование MAX для событий групп. [События MAX](https://dev.max.ru/docs-api/methods/GET/updates).

## 3. Узнать ID чатов

В переменных окружения стека Portainer сначала задайте `TELEGRAM_BOT_TOKEN` и `MAX_BOT_TOKEN`; оставьте оба флага `*_ENABLED=false`. Обновите стек, чтобы контейнеры получили токены. Токены в исходники и инструкции не вставляются.

Сразу после добавления бота откройте консоль контейнера **web** в Portainer и выполните соответствующую команду:

```sh
python manage.py bot_chat_id telegram
python manage.py bot_chat_id max
```

Команда выведет ID и название чата либо тип события. Выберите ID именно офисной группы. Это разовое чтение событий при подключении: команда не отправляет сообщения, не меняет вебхуки и не подтверждает старые события через offset/marker. Для MAX без marker доступно последнее событие, поэтому выполните команду сразу после добавления бота. Если данных нет, повторите действие в нужном чате и команду. [Telegram getUpdates](https://core.telegram.org/bots/api#getupdates), [MAX updates](https://dev.max.ru/docs-api/methods/GET/updates).

## 4. Включить отправку в Portainer

| Переменная | Значение |
|---|---|
| `PUBLIC_URL` | `https://srez.studio313.ru` |
| `TELEGRAM_BOT_TOKEN` | Токен из BotFather |
| `TELEGRAM_CHAT_ID` | ID офисной группы Telegram, включая минус, если он есть |
| `TELEGRAM_ENABLED` | `true` |
| `MAX_BOT_TOKEN` | Токен из настроек MAX-бота |
| `MAX_CHAT_ID` | ID офисной группы MAX |
| `MAX_ENABLED` | `true` |

Обновите стек. Можно включить сначала один канал. В сервисе откройте «Управление» → «Уведомления»: для настроенного канала появится «Отправка включена». Успешную доставку подтверждает время последней отправки, а не только этот статус.

MAX использует `https://platform-api2.max.ru`, токен передаётся в заголовке Authorization. Если системное хранилище контейнера не доверяет сертификату MAX, подготовьте доверенный CA bundle по официальным указаниям провайдера, подключите его в **web и worker** как read-only volume и задайте `MAX_CA_BUNDLE=/run/certs/max-ca-bundle.pem`. Проверка TLS не отключается. [Требования API MAX](https://dev.max.ru/docs-api/methods/POST/messages).

## 5. Проверить на пилоте

Подтвердите графики пилотных магазинов и дату начала контроля. При первом реальном событии проверьте сообщение в обоих чатах и ссылку: она должна открывать нужный магазин, дату и время. До создания ботов эта проверка остаётся невыполненной.

События: отчёт не получен в подтверждённый срок; первый отчёт получен поздно; необычные показатели; ответ продавца на вопрос офиса. Пустые исторические строки без сроков остаются в интерфейсе и не превращаются в новые уведомления об опоздании.

У каждого канала своя очередь и время отправки. Ошибка Telegram не останавливает MAX. После ошибки запрос повторяется с задержкой; после подтверждённого успеха сообщение повторно не отправляется. При сетевом тайм-ауте возможен повтор уже доставленного сообщения, поскольку API не гарантирует подтверждение при потере связи. Закрытые замечания и архивные магазины из отправки исключаются.

Если отправка не идёт, проверьте статус и последнюю ошибку в «Уведомлениях», включённый контроль графика, права бота в чате и доступ сервера к API. Регулярные сводки и индивидуальные чаты магазинов в этот этап не входят.
